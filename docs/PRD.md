# 빈티지 디카 작례 사이트 — PRD

> 상태: 초안 (MVP 범위 확정) · 작성일: 2026-11-12
>
> 목표: 포트폴리오가 아니라 **실제로 배포·운영해서 사용자를 받는 서비스**

## 1. 한 줄 소개

**디카 사기 전에, 그 기종으로 진짜 찍은 작례를 한국어로 모아 보는 곳.**

## 2. 문제 정의

디카 감성이 유행하면서 2000년대~2010년대 초 똑딱이(소형 디지털카메라)를 사려는 사람이 늘었다. 하지만 "이 카메라로 찍으면 어떤 느낌인지" 사기 전에 미리 보기 어렵다.

- **작례가 흩어져 있다**
  - 인스타, 블로그, 커뮤니티에 흩어져 있고 기종별로 정리돼 있지 않다.
  - 인스타 사진은 EXIF가 지워져서 진짜 그 카메라로 찍었는지, 보정했는지 알 수 없다.
- **이름이 제각각이라 검색이 안 된다**
  - 같은 카메라도 나라마다 이름이 다르다. (IXY / IXUS / PowerShot SD)
  - 삼성 케녹스, 블루(VLUU)처럼 국내에서 많이 팔린 기종은 작례가 적거나 다른 이름으로 올라가 있다.
- **해외 사이트는 쓰기 어렵다**
  - Flickr 같은 해외 사이트는 영어 UI이고, 크롬 자체 번역도 제대로 되지 않는다.
  - 요즘 카메라·폰 위주라 빈티지 디카는 직접 찾아야 한다.
- **요즘 한국에서 어떤 디카가 인기인지 한눈에 볼 곳이 없다.** (이 문제는 추후 기능에서 다룬다. [LATER.md](./LATER.md))

### 대상 카메라 범위

- **2000년대~2010년대 초 똑딱이** (CCD 위주, CMOS 포함)
  - 국내 인기 기종에 2010년대 초 CMOS 슬림 똑딱이(예: 캐논 익서스 230 HS·310 HS)가 들어 있어 CCD만으로 한정하지 않는다.
  - 센서 종류(CCD/CMOS)는 기종 정보로 보여준다.
- 대형 센서 고급 카메라(예: 후지필름 X100), DSLR·미러리스는 넣지 않는다. 시장과 가격대가 다르다.
- 초기 기종 30개는 [CAMERAS.md](./CAMERAS.md)

## 3. 대상 사용자

- 빈티지 디카 구매를 고민 중인 사람: 기종별 작례를 보고 고르고 싶다.
- 이미 빈티지 디카를 쓰는 사람: 찍은 사진을 기종별로 공유하고 싶다.

## 6. 기능 요구사항

### F1. 홈

- 검색창 (F2), 브랜드 목록 (F2)
- **최근 올라온 작례**: 사용자가 올린 작례를 최신순 격자로 보여준다. 작례를 누르면 작례 상세로 간다.
  - 사용자 업로드가 아직 적은 출시 직후에는 이 영역을 숨기거나 있는 만큼만 보여준다.
- 원래 계획한 "요즘 뜨는 디카" 순위는 추후 기능으로 뺐다. ([LATER.md](./LATER.md))

### F2. 기종 검색 / 브랜드별 목록

- 홈의 검색창에서 기종을 검색한다.
- 공식 모델명뿐 아니라 **별칭으로도 검색된다.**
  - 예: "익서스", "IXUS", "PowerShot SD"로 검색해도 IXY 기종이 나온다.
  - 국내 판매명 포함 (케녹스, 블루 등)
- 브랜드를 고르면 그 브랜드의 기종 목록을 보여준다.

### F3. 기종 페이지

- 그 기종으로 찍은 작례를 격자로 모아 보여준다. (EXIF로 그 기종에서 찍은 게 확인된 사진만)
- 사용자 업로드와 Commons 작례를 함께 보여준다. Commons 작례에는 출처를 표시한다.
- 한 번에 24장씩 보여준다. (3·4·6칸 격자로 모두 나누어떨어짐)
- **플래시 필터**: 플래시 사용 / 미사용으로 걸러볼 수 있다.
  - EXIF의 Flash 태그로 판별한다. Commons 작례도 API로 EXIF를 받을 수 있어 같은 방식으로 판별한다.
  - Flash 태그가 없는 작례는 필터를 걸면 빠진다.
- **원본 크기 필터** ("원본 크기만 보기"): 카메라가 찍은 크기 그대로인 사진만 보여준다.
  - 기본은 필터 없이 **작게 줄인 사진까지 모두** 보여준다.
  - 작게 줄인 사진은 노이즈·선명도·색감 같은 카메라 특성이 일부 지워져 있어서, 화질을 꼼꼼히 보고 싶은 사람은 이 필터를 켠다.
  - 판별 기준: 사진의 긴 변이 **그 기종의 원래 해상도(긴 변)의 95% 이상**이면 원본 크기. (살짝 잘라 낸 사진까지 허용) 기종의 원래 해상도를 모르면 판별하지 않고 필터에서 빠진다.
  - 단순히 "1024px 이상" 같은 기준을 쓰지 않는 이유: 원본보다 줄였지만 꽤 큰 사진도 "원본"으로 표시되어 이름과 맞지 않기 때문이다.
  - 사용자 업로드도 같은 기준으로 판별한다. (카메라에서 바로 옮긴 원본이면 대부분 원본 크기)

### F4. 작례 상세

- 사진을 크게 보여준다. (보기용 긴 변 1600px. 원본 파일은 보여주지 않음)
  - 1600px보다 작은 사진은 **늘리지 않고 원래 크기로** 보여준다. 늘리면 흐려져서 카메라 특성을 잘못 보게 된다.
- **다운로드 기능은 없다.** 다운로드 버튼이나 원본 보기를 두지 않는다. 다만 화면에 보이는 사진의 우클릭 저장·캡처는 브라우저 특성상 완전히 막을 수 없으므로, 무단 사용은 이용약관과 신고로 대응한다.
- 촬영 정보: 기종, 촬영일, 플래시 여부, 노출 정보(EXIF에 있는 만큼)
- **옆으로 넘기면** 같은 기종의 이전·다음 작례로 바뀐다. 기종 페이지에서 고른 필터(플래시, 원본 크기만)를 그대로 따른다. 휴대폰은 손가락으로 밀고, 데스크톱은 화살표 버튼이나 키보드 ← →로 넘긴다. 넘겨도 뒤로 가기를 누르면 기종 페이지로 돌아간다.
- 올린 사람의 프로필로 이동할 수 있다.
- Commons 작례는 **작가 이름, 라이선스(링크 포함), 원본 파일 페이지 링크**를 표시하고, 크기를 줄인 사진이라는 것도 적는다. (예: "사진: John Doe · CC BY-SA 4.0 · Wikimedia Commons · 크기 조정됨")

### F5. 작례 올리기

- 로그인한 사용자만 올릴 수 있다. 로그인은 **구글, 카카오** 두 가지로 한다.
  - 구글·카카오 모두 **회원번호만** 받는다. 이메일·닉네임·프로필 사진은 받지 않는다. 닉네임은 가입 화면에서 직접 정한다. (카카오 닉네임은 실명인 경우가 많아 그대로 공개되지 않게)
- 원본 사진을 올리면 EXIF의 카메라 모델로 **기종을 자동 인식**한다.
  - 인식 결과를 보여주고 사용자가 확인한 뒤 올린다.
- EXIF가 없으면 올릴 수 없고, "인스타 등에서 받은 파일은 촬영 정보가 지워져 있어요. 카메라에서 옮긴 원본 파일을 올려주세요" 같은 안내를 보여준다.
- **GPS 등 위치 정보는 지운 뒤 저장한다.** DB뿐 아니라 저장하는 이미지 파일에서도 지운다.
- 올린 작례는 기종 페이지와 올린 사람의 프로필 피드에 동시에 올라간다.
- **등록되지 않은 기종일 때**: 업로드는 받고 **미분류** 상태로 둔다.
  - EXIF 원문(제조사, 모델명)을 저장하고, 올린 사람의 프로필에는 바로 보여준다. 기종 페이지에는 아직 안 올라간다.
  - 관리자가 확인한 뒤 새 기종으로 만들거나 기존 기종의 별칭으로 연결한다.
  - 연결하면 같은 EXIF 모델명의 미분류 작례가 전부 그 기종에 자동으로 붙는다.
  - 바로 기종을 자동 생성하지 않는 이유: 폰 사진(예: iPhone 15)도 EXIF가 있어서 엉뚱한 기종 페이지가 생기고, 같은 기종이 여러 이름으로 쪼개진다.

### F6. 프로필 피드

- 그 사람이 올린 작례를 인스타 피드처럼 격자로 보여준다.
- 미분류 작례도 보여주고 "기종 확인 중"으로 표시한다.
- 본인이 올린 작례는 **직접 삭제**할 수 있다.

### F7. 초기 작례 수집 (콜드 스타트)

- **Wikimedia Commons**(위키미디어 공용, 자유 라이선스 사진 저장소)에서 초기 기종 30개의 작례를 가져온다.
  - 기종별 "Taken with ○○" 분류에 있는 사진을 가져온다.
  - EXIF의 카메라 모델이 해당 기종과 맞는 사진만 고른다.
  - 2026-11-17 확인 결과: 소니·후지필름·캐논(Digital IXUS 이름)·니콘은 기종당 수백~수천 장, 삼성·카시오는 기종당 100장 안팎. 캐논 IXY(일본 이름), 삼성 케녹스·블루(국내 이름)로는 거의 안 나와서 **해외 모델명으로 찾아야** 한다.
- **Flickr 대신 Commons를 쓰는 이유**: Flickr는 무료 계정의 API 키 발급을 막아 두어 Pro 구독이 필요하다. Commons는 키가 필요 없고, 자유 라이선스라 사진 파일을 우리 저장소에 둘 수 있으며, 나중에 광고를 붙여도 문제가 없다.
- **허용하는 라이선스만** 가져온다: 퍼블릭 도메인, CC0, CC BY, CC BY-SA. 그 외(GFDL 단독 등 조건이 복잡한 것)는 건너뛴다.
- **작은 사진도 가져온다.** 대신 원본 크기인지 판별해서 표시하고(F3 원본 크기 필터), 너무 작은 사진(긴 변 400px 미만)만 버린다. 휴대폰 3칸 격자 한 칸에 고화질 화면 기준 약 400px가 필요해서, 그보다 작으면 썸네일도 흐리게 나온다.
- **작가가 고르게 섞이게** 고른다. 작가별로 돌아가며 한 장씩, 기종당 한 작가는 최대 10장. 한 사람 사진이 몰리면 카메라가 아니라 그 사람의 습관을 보게 된다.
- PoC 결과(2026-11-17): 기종당 33~100장을 확보할 수 있었다. 다만 거리·건물 같은 기록용 사진이 대부분이라 **"디카 감성" 작례는 사용자 업로드가 채워야** 한다.
- **사진 파일을 우리 R2에 저장한다.** 썸네일과 보기용을 만들어 사용자 업로드와 똑같이 보여준다. 원본은 저장하지 않는다. (필요하면 Commons에서 다시 받으면 됨)
- 표시 의무: 작가 이름, 라이선스 이름과 링크, 원본 파일 페이지 링크, 크기를 바꿨다는 표시 (F4)
- 주기적으로 실행하는 배치로 만든다.
  - 수집 배치: 새 작례 가져오기
  - 정리 배치: Commons에서 삭제된 파일(저작권 문제 등)을 확인해서 우리 쪽에서도 지운다.
- 저작권자가 삭제를 요청하면 관리자가 바로 지운다.
- 초기 기종 30개 선정: Reddit r/VintageDigitalCameras와 국내 인스타·커뮤니티에서 후보를 뽑고, Commons에 작례가 충분한지 확인해 추린다.
- 장기적으로는 사용자 업로드가 주력이 되도록 한다. 출시 전에 친구·지인, 디카 커뮤니티에서 초기 작례를 직접 모은다.

### F8. 신고와 관리자 처리

남이 올린 사진을 보여주는 서비스라 부적절한 사진, 남의 사진 도용, 초상권 문제가 반드시 생긴다. 출시할 때부터 처리 수단이 있어야 한다.

- 작례 상세에 **신고 버튼**을 둔다. 로그인한 사용자만 신고할 수 있다.
  - 신고 사유: 부적절한 사진 / 내가 찍은 사진 도용 / 초상권 침해 / 해당 기종 사진 아님 / 기타
- 관리자는 신고 목록을 보고 작례를 삭제하거나 신고를 기각한다.
- 관리자 기능은 **화면 없이 관리자 권한(ADMIN) API**로 만들고 Swagger UI에서 호출한다. 처리량이 많아지면 화면을 붙인다.
- 관리자 API로 처리하는 일:
  - 신고 처리 (삭제 / 기각)
  - 미분류 작례를 기종에 연결 (F5)
  - Commons 작례의 저작권자 삭제 요청 처리 (요청을 받으면 바로)

### F9. 법적 고지

- **개인정보처리방침**: 소셜 로그인으로 회원 정보를 받으므로 개인정보보호법상 필수다. 방문 통계(Google Analytics 4) 사용 사실도 적는다.
- **이용약관**: 업로드한 사진의 권리, 금지 행위(남의 사진 업로드, 초상권 침해), 신고가 들어오면 삭제할 수 있다는 내용
- **업로드 동의 문구**: 업로드 화면에 "직접 찍은 사진만 올려주세요. 사람이 나온 사진은 당사자 동의를 받아주세요" 같은 안내와 동의 체크
- 푸터: 개인정보처리방침, 이용약관 링크. "일부 작례는 Wikimedia Commons의 자유 라이선스 사진입니다" 안내 (사진별 출처 표시는 F4)

### F10. 회원 탈퇴

- 프로필 페이지(내 페이지)에서 탈퇴할 수 있다.
- 탈퇴하면 **개인정보와 그 사용자가 올린 작례를 모두 삭제**한다. 사진 파일도 저장소에서 지운다.
- 탈퇴 전에 "올린 작례 N장이 모두 삭제되고 되돌릴 수 없어요" 같은 확인을 받는다.
- 그 사용자가 남긴 신고 기록은 남기고, 신고자는 "탈퇴한 사용자"로 표시한다.

## 7. 페이지 구조 (6개)

```
홈 (검색창 + 브랜드 목록 + 최근 올라온 작례)
├─ 브랜드 선택 → 브랜드 페이지 (기종 목록) → 기종 페이지
├─ 기종 검색 → 기종 페이지 (작례 모아보기, 플래시 필터, 원본 크기 필터)
│                 └─ 작례 선택 → 작례 상세
└─ 내 페이지 → 프로필 페이지 (작례 피드)
                  ├─ 피드에서 선택 → 작례 상세
                  └─ 업로드 → 작례 올리기 → (완료 후) 작례 상세
```

이 밖에 정적 페이지: 개인정보처리방침, 이용약관

## 8. 사용 시나리오

1. A가 인스타에서 본 디카 이름("익서스 30")을 홈에서 검색해 익서스 30 페이지로 간다.
2. 익서스 30 페이지에서 플래시 작례만 걸러보고, 마음에 들어서 익서스 30을 산다.
3. 친구들을 찍은 원본을 올리면 익서스 30으로 자동 인식돼서 기종 페이지와 A의 피드에 동시에 올라간다.
4. 다음에 익서스 30을 고민하는 사람은 A의 작례를 보고 결정한다.

## 9. 데이터 출처와 정책

| 출처 | 용도 | 주의할 점 |
|---|---|---|
| 사용자 업로드 | 주 작례 | GPS 삭제, 원본 파일만 허용. Cloudflare R2에 썸네일·보기용(공개)과 원본(비공개) 저장. 다운로드 기능 없음 |
| Wikimedia Commons | 초기 작례 | 키 불필요. 허용 라이선스(PD, CC0, CC BY, CC BY-SA)만. 썸네일·보기용을 R2에 저장. 작가·라이선스·원본 링크·크기 조정 표시. API 요청 시 서비스 식별 정보(User-Agent)를 붙이고 천천히 요청. Commons에서 삭제된 파일은 주기적으로 정리 |
| 인스타 | 사용하지 않음 | 사진은 가져오지 않고, 작례 올려줄 사람을 모으는 홍보 채널로만 사용 |

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 초기 작례가 없어 기종 페이지가 비어 있음 | Commons로 채우고, 출시 전 지인·커뮤니티에서 직접 모음 |
| 국내 기종(케녹스 등)은 Commons에 적음 | 해외 모델명으로 찾고, 그래도 부족하면 지인·커뮤니티 작례로 채움. 그래도 많이 부족하면 Flickr Pro 검토 |
| Commons 사진 중 작례로 쓰기 애매한 사진 (제품 사진, 문서 스캔 등) | 기종별로 가져온 사진을 출시 전에 훑어보고 관리자가 지움 |
| 진짜 그 기종으로 찍었는지 확인 | EXIF 카메라 모델로 자동 판별 (디지털이라 가능) |
| EXIF가 지워진 파일 업로드 | 업로드 거부와 원본 파일 안내 |
| 위치 정보 노출 | 저장 전 GPS 삭제 |
| Commons 라이선스 표시 누락 | 작가·라이선스·원본 링크가 없으면 저장하지 않음. 화면에서 항상 함께 표시 |
| 미등록 기종·폰 사진 업로드 | 미분류로 받고 관리자가 기종 생성 또는 별칭 연결 |
| 부적절한 사진, 도용, 초상권 침해 | 신고 기능과 관리자 삭제, 이용약관과 업로드 동의 문구 |
| 도배·악성 업로드 | 파일 크기·형식 검사, 업로드 횟수 제한 |
| 서버 장애로 데이터 손실 | 관리형 DB의 자동 백업 사용 |

## 11. 경쟁 서비스

**해외**
- **Flickr Camera Finder**: EXIF로 사진을 기종별로 분류. 사실상 가장 큰 경쟁자. 영어이고 번역이 잘 안 되며, 인기 기종 정보가 없음.
- **ExploreCams**: Flickr, 500px, Pixabay 메타데이터로 카메라 통계와 작례 제공 (약 700만 장). 수집 방식이 우리와 거의 같음.
- **SampleShots / PhotoWorkout**: 카메라 573종의 스펙과 작례. 현행 카메라 위주라 빈티지 디카 작례는 적음 (예: Coolpix S32는 3장).
- **Digital Camera Museum 등**: 스펙·역사 위주, 작례는 약함.

**국내**
- **인스타 해시태그, 블로그, 디카 커뮤니티**: 사실상 직접 경쟁자. 작례는 많지만 흩어져 있고 기종별 정리가 없음.
- 찾아본 범위에서는 국내에 기종별 작례를 정리한 사이트가 없음.

## 12. 기술 방향 (상세는 [ARCHITECTURE.md](./ARCHITECTURE.md))

- 프론트엔드: Next.js + TypeScript + Tailwind CSS (검색 노출 때문에 서버 렌더링)
- 화면: 휴대폰·데스크톱을 따로 만들지 않고 **반응형 웹 하나**로 만든다. 휴대폰 화면을 먼저 만든다. (모바일 우선)
- 백엔드: Spring Boot + JPA
- 로그인: 구글, 카카오 (OAuth2)
- 이미지 저장소: Cloudflare R2
- 외부 API 배치: Wikimedia Commons(작례)
- 배포: Vercel(프론트), AWS Lightsail 2GB + Docker(백엔드), Lightsail 관리형 PostgreSQL(DB)
- 운영: 도메인(DNS는 Cloudflare), Sentry(에러 추적), Google Analytics 4(방문 통계), GitHub Actions(자동 배포)
- 예산: **출시 후 월 약 $25 + 도메인** (개발 기간에는 로컬에서 개발해 비용 없음)

## 13. 성공 기준

> Commons에 사진이 없는 인기 기종(익서스 230 HS·310 HS, 작티 J1·DMX-C40)은 출시 전 장수 목표에 넣지 않는다. 지인·커뮤니티에서 모은 만큼 넣고, 없으면 "첫 작례를 올려주세요" 상태로 출시한다.

| 시점 | 기준 | 의미 |
|---|---|---|
| 출시 전 | **Commons로 채울 수 있는 기종(26개)은 모두 작례 20장 이상** | 콜드 스타트 해결 |
| 출시 후 1개월 | 사용자 업로드 작례 100장 | 사용자가 직접 올리기 시작함 |
