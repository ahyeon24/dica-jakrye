# 빈티지 디카 작례 사이트 — 보안 체크리스트

> 상태: 초안 · 작성일: 2026-11-17 · 관련 문서: [ARCHITECTURE.md](./ARCHITECTURE.md), [API.md](./API.md), [ERD.md](./ERD.md)
>
> 개발하면서, 그리고 출시 전에 이 목록을 확인한다. 기능을 새로 만들 때는 해당 항목을 다시 본다.

## 1. 인증과 인가

- **인증**: "누구인가" (로그인) / **인가**: "이걸 해도 되는가" (권한)
- 로그인 여부만 확인하고 권한 확인을 빼먹는 실수가 가장 흔하다. 주소의 숫자만 바꿔 남의 데이터를 건드리는 공격(**IDOR**)으로 이어진다.

```
DELETE /api/photos/1043   ← 내 작례
DELETE /api/photos/1044   ← 숫자만 바꿔 남의 작례 삭제 시도
```

- [ ] 작례 삭제: 서버에서 **올린 사람 본인인지** 확인한다. 아니면 `403 NOT_PHOTO_OWNER`
- [ ] 신고: 본인 작례는 신고할 수 없다.
- [ ] `/api/admin/**`: **ADMIN 권한**을 Spring Security 설정에서 경로 단위로 막는다. 컨트롤러마다 따로 확인하다 빠뜨리지 않게 한다.
- [ ] 프론트에서 버튼을 숨기는 것은 보안이 아니다. 모든 권한 확인은 서버에서 한다.
- [ ] 탈퇴한 사용자의 세션은 즉시 끊는다.

## 2. 사용자 입력은 믿지 않는다

**값 바꿔치기 (Mass Assignment)**

```json
PATCH /api/me
{ "nickname": "새닉네임", "role": "ADMIN" }   ← role을 몰래 끼워 넣음
```

- [ ] 요청 본문을 엔티티에 바로 담지 않는다. **API마다 받을 필드만 정의한 요청 DTO**를 쓴다.
- [ ] 모든 요청 DTO에 길이·형식 검증(`@Valid`, `@Size`, `@Pattern` 등)을 붙인다. (닉네임 2~20자, 신고 상세 500자 등)

**SQL 인젝션**

- [ ] JPA 메서드나 `@Query`의 **파라미터 바인딩**(`:keyword`)만 쓴다.
- [ ] SQL 문자열을 이어 붙여 만들지 않는다. 특히 **기종 검색**처럼 검색어가 들어가는 쿼리.
- [ ] 정렬 기준 같은 값을 사용자에게 받아야 하면 허용 목록에 있는 값만 받는다.

## 3. XSS (스크립트 심기)

- 사용자가 입력한 값(닉네임, 신고 내용 등)에 스크립트를 넣어 다른 사용자 브라우저에서 실행시키는 공격.
- [ ] React(Next.js)는 화면에 출력할 때 기본으로 안전하게 처리한다. **`dangerouslySetInnerHTML`은 쓰지 않는다.**
- [ ] 약관 같은 본문을 마크다운으로 렌더링한다면, HTML을 허용하지 않는 설정으로 쓴다.
- [ ] **외부에서 가져온 값도 사용자 입력처럼 다룬다.** Commons의 작가 정보(`Artist`)에는 HTML 태그와 링크가 섞여 오므로, **저장하기 전에 태그를 모두 지우고 글자만** 남긴다. 화면에서 HTML로 그리지 않는다.
- [ ] 로그인 세션 쿠키는 `HttpOnly`로 자바스크립트가 읽지 못하게 한다. (스크립트가 심어져도 세션은 못 훔침)

## 4. CSRF와 쿠키

상세는 [API.md](./API.md) 1.2, 1.3.

- [ ] 세션 쿠키: `HttpOnly`, `Secure`, `SameSite=Lax`, `Domain=.{도메인}`
- [ ] 로컬 설정에서는 `Secure`, `Domain`을 끄고 운영 설정에서만 켠다. (`application-local.yml` / `application-prod.yml`)
- [ ] 쓰기 요청(POST, PATCH, DELETE)은 CSRF 토큰(`X-XSRF-TOKEN` 헤더)을 확인한다.
- [ ] GET 요청은 데이터를 바꾸지 않는다. (CSRF 토큰 검사를 안 하므로)

## 5. 파일 업로드

상세는 [ARCHITECTURE.md](./ARCHITECTURE.md) 3.1, 6장 업로드 보안.

- [ ] 파일 크기 제한: 20MB
- [ ] 확장자·Content-Type이 아니라 **파일 내용으로** JPEG인지 확인
- [ ] **이미지 폭탄 막기**: 파일은 작은데 픽셀이 엄청나게 많아서, 열면 메모리가 터지는 이미지가 있다.
  - 이미지를 메모리에 올리기 **전에** 파일 헤더에서 가로·세로를 먼저 읽는다.
  - **가로×세로가 4,000만 픽셀(40MP)을 넘으면 거부**한다. (`400 IMAGE_DIMENSIONS_TOO_LARGE`) 빈티지 디카는 대부분 16MP 이하라 정상 사용자는 걸리지 않는다.
  - 업로드 처리를 동시에 몇 개까지 할지 제한한다. (2GB 서버에서 여러 장을 한꺼번에 열지 않게)
- [ ] 저장 파일명은 서버가 새로 만든다. 사용자가 보낸 파일명은 쓰지 않는다. (`../../` 같은 경로 조작 방지)
- [ ] 원본은 GPS만 지워 비공개 버킷에, 썸네일·보기용은 EXIF를 모두 지워 공개 버킷에 저장한다.
- [ ] 업로드 중 만든 임시 파일은 요청이 끝나면 성공·실패와 관계없이 지운다.
- [ ] 업로드 횟수 제한(1시간 30장)은 DB에서 센다.

## 6. 로그인 후 이동 주소 검증 (Open Redirect)

"로그인하면 원래 보던 페이지로 돌아간다"를 주소 파라미터로 구현하면 이런 공격이 가능하다.

```
https://{도메인}/login?redirect=https://해커사이트.com
```

사용자는 우리 사이트에서 로그인했는데 해커 사이트로 넘어가고, 거기 있는 가짜 화면에 속기 쉽다.

- [ ] 돌아갈 주소는 **우리 사이트 내부 경로만** 허용한다.
  - `/`로 시작해야 한다.
  - `//`나 `/\`로 시작하면 안 된다. (브라우저가 다른 사이트 주소로 해석함)
  - 조건에 맞지 않으면 홈(`/`)으로 보낸다.
- [ ] 이동 주소는 로그인 시작 시 서버 세션에 저장해 두고, 로그인 완료 후 세션에서 꺼내 쓴다.

## 7. OAuth 로그인

- [ ] 구글·카카오 콘솔에 등록하는 **콜백 주소는 정확한 전체 주소**로 등록한다. (와일드카드 사용 안 함)
- [ ] 운영 콜백 주소는 HTTPS. 로컬은 `http://localhost:8080`만 따로 등록한다.
- [ ] OAuth `state` 검증은 Spring Security가 해 준다. 직접 OAuth 흐름을 구현하지 않는다.
- [ ] 약관 동의 전에는 회원을 만들지 않는다. (가입 대기 정보만 세션에)

## 8. 비밀 정보 관리

대상: 구글·카카오 클라이언트 시크릿, R2 접근 키, DB 비밀번호, 세션·쿠키 관련 비밀값

- [ ] **Git에 절대 올리지 않는다.** 공개 저장소에 올라가면 자동 수집 봇이 몇 분 안에 가져간다.
- [ ] 로컬: `.env` 또는 `application-local.yml`에 두고 `.gitignore`에 넣는다. 예시 파일(`.env.example`)에는 키 이름만 적는다.
- [ ] 운영: 서버 환경변수와 GitHub Actions Secrets에 둔다.
- [ ] **실수로 올렸으면 커밋을 지우는 게 아니라 그 키를 즉시 폐기하고 새로 발급한다.** Git 기록에 남기 때문이다.
- [ ] 저장소에 GitHub Secret scanning(비밀 정보 감지)을 켠다.

## 9. 권한 최소화

- [ ] **R2 접근 키**: 우리 버킷 두 개에만 접근하도록 범위를 제한한다.
- [ ] **DB**: 인터넷에서 직접 접속할 수 없게 막고 Lightsail 서버에서만 접속한다. 앱용 DB 계정에는 관리자 권한을 주지 않는다.
- [ ] **Lightsail 방화벽**: 80, 443만 연다. SSH(22)는 내 IP에서만, 비밀번호가 아니라 키로 로그인한다.
- [ ] **Swagger UI**: 운영에서는 ADMIN 로그인 상태에서만 열린다.
- [ ] **관리자 계정**: 필요한 사람만. 처음 관리자 지정은 DB에서 직접 한다. (관리자를 만드는 API는 두지 않음)

## 10. CORS

프론트(`{도메인}`)와 API(`api.{도메인}`)가 달라서 API 서버가 허용할 도메인을 알려줘야 한다.

- [ ] **우리 프론트 도메인만** 허용한다. 모든 도메인(`*`)을 허용하지 않는다.
- [ ] 쿠키를 쓰므로 `allowCredentials(true)`. (이 설정은 `*`와 같이 쓸 수 없다)
- [ ] 로컬은 `http://localhost:3000`만 허용한다.

## 11. 에러와 로그

- [ ] 에러 응답에 스택 트레이스, SQL 오류, 내부 클래스 이름을 내보내지 않는다. `{ code, message }` 형식만.
- [ ] 로그에 세션 ID, 쿠키, API 키, OAuth 토큰을 남기지 않는다.
- [ ] 로그에 개인정보를 필요 이상 남기지 않는다. 사용자는 회원 ID로만 기록한다.
- [ ] Sentry로 보내는 데이터에도 같은 기준을 적용한다. (요청 헤더·쿠키 전송 끄기)

## 12. 라이브러리 취약점

- [ ] GitHub **Dependabot**을 켜서 취약한 버전을 쓰면 알림을 받는다.
- [ ] 특히 **이미지·EXIF 처리 라이브러리**는 외부 파일을 직접 다루므로 업데이트를 미루지 않는다.
- [ ] Spring Boot, Next.js는 보안 패치가 나오면 빠르게 올린다.

## 12-1. 외부 서비스 이용 규칙

- [ ] Wikimedia Commons에 요청할 때 User-Agent에 서비스 이름과 연락처를 넣는다. 연락처에는 개인 이메일 대신 운영용 이메일이나 서비스 주소를 쓴다.
- [ ] Commons 요청은 순서대로 하나씩, 이미지 다운로드는 1초에 1장 이하. 막히면 대기 시간을 늘려 다시 시도한다. ([ARCHITECTURE.md](./ARCHITECTURE.md) 3.3)
- [ ] Commons 작례는 작가·라이선스·원본 링크·크기 조정 표시가 빠지지 않게 한다. 정보가 없는 사진은 저장하지 않는다.
- [ ] 네이버 데이터랩(NCP API HUB)은 MVP에서 쓰지 않는다. 검증용 키는 `poc/.env`에만 있고 Git에 올리지 않는다. NCP 계정에는 결제 수단이 등록되어 있으므로 예산 알림을 켜 두고 다른 서비스는 만들지 않는다. 다시 쓸 때의 주의사항은 [LATER.md](./LATER.md).

## 13. 개인정보

- [ ] 받는 정보는 최소한으로: 소셜 로그인 회원번호, 닉네임. 이메일은 저장하지 않는다.
- [ ] 사진의 GPS는 저장 전에 지운다.
- [ ] 탈퇴하면 개인정보와 작례(파일 포함)를 지운다.
- [ ] 개인정보처리방침에 수집 항목, 이용 목적, 보관 기간, 방문 통계(GA4) 사용 사실을 적는다.

## 14. 출시 전 최종 점검

- [ ] 위 항목 전체 확인
- [ ] 다른 계정으로 로그인해서 남의 작례 삭제, 관리자 API 호출이 막히는지 직접 시도
- [ ] 로그아웃·탈퇴 후 이전 세션 쿠키로 요청이 거부되는지 확인
- [ ] 이미지 폭탄 파일, JPEG가 아닌 파일, EXIF 없는 파일 업로드가 거부되는지 확인
- [ ] 공개 이미지 파일에 EXIF가 남아 있지 않은지 확인
- [ ] Commons 작례 상세에 작가·라이선스·원본 링크가 모두 보이는지, 작가 이름에 HTML이 섞여 나오지 않는지 확인
- [ ] `/login?redirect=https://example.com`이 홈으로 가는지 확인
- [ ] Git 기록 전체에 비밀 정보가 없는지 확인
- [ ] 운영 서버 방화벽과 DB 외부 접속 차단 확인
